Before spinning up the cluster, you must lock down the execution environment and manage API quotas. Autonomous code generation can quickly escalate into runaway API costs or compromised host environments if agents are left completely unchecked.Here are the critical safeguards to implement before you start writing the core agent logic.1. Execution Isolation (The Blast Radius)When the Builder Agent compiles and executes unknown, synthesized code inside Docker, the host hardware needs strict boundaries.Network Restriction: Inside the execution sandbox, block outbound traffic to unknown destinations and only allow-list specific domains like package registries. This prevents a hallucinated or malicious dependency from exfiltrating data.   Read-Only Vault Access: The Scavenger and Innovator need write access to the Obsidian Brain, but the Builder Agent should mount the /Synthesized/ directory as read-only. It should only execute the code, never overwrite the architectural blueprints.Non-Root Containers: Always run the Builder's output containers as a non-root user (using the USER directive in the generated Dockerfiles) to prevent privilege escalation on the host nodes.   2. Centralized Rate LimitingUnmanaged rate limiting is the primary cause of multi-agent pipeline failures. If the Scavenger is querying the LLM for architectural summaries while the Innovator is synthesizing a large blueprint, they will hit a 429 Too Many Requests error and crash.   Shared Token Bucket: Implement a centralized rate limit tracker across all agents. If the system approaches the API provider's limit, it should queue requests rather than dropping them.Exponential Backoff: If an agent receives a 429 error, it must wait 1 second, then 2, then 4, adding a random "jitter" (e.g., waiting 4.2 seconds instead of exactly 4) to avoid synchronized retry spikes across the cluster.   3. Scoped Agent IdentitiesDo not share a single master API key or credential across the entire pipeline. Provision agents with dedicated, scoped credentials that carry only the permissions the specific task requires.   The Scavenger receives a scoped GitHub Personal Access Token strictly to read repositories.The Innovator receives the LLM API key to generate the logic.The Builder receives access to the local Docker socket, but zero access to the LLM or GitHub. If the Builder goes rogue executing a bad loop, it cannot rack up API bills or delete remote repositories.4. Human-in-the-Loop CheckpointsBefore allowing the Builder to autonomously spin up containers on the hardware, insert a circuit breaker.When the Innovator finishes dropping a unified blueprint into the /Synthesized/ directory, have it trigger a simple Discord webhook or a command-line prompt.This allows you to manually review the architectural logic and approve the deployment before the Docker network begins consuming hardware resources.
